# Proto Endpoints

The `Networking` package exposes a **parallel proto decode path** alongside the existing JSON path. Use it for any endpoint whose server returns `application/x-protobuf` (i.e. a BSR-generated binary proto response). The JSON `fetch<T: Decodable>` path remains for not-yet-migrated endpoints.

> **Module split:** `WireMessage` lives in **`Networking`** (abstraction, no SwiftProtobuf import); the implementation lives in **`NetworkingLive`**; generated message types live in the separate **`WireModels`** package.

## WireMessage Protocol

`WireMessage` is defined in `Networking` — **without** importing SwiftProtobuf — so that every feature package can depend on the abstraction without pulling the SwiftProtobuf runtime:

```swift
// Networking/Decoding/WireMessage.swift
public protocol WireMessage: Sendable {
    init(serializedBytes: some Collection<UInt8>) throws
}
```

The generated Swift message types (from `buf.build/apple/swift`) satisfy this requirement. Conformances are declared in `WireModels`, not in `Networking`:

```swift
// WireModels/WireMessage+Generated.swift  (in the WireModels package)
import Networking
import SwiftProtobuf   // only here, not in Networking

extension Auth_AuthenticateResponse: WireMessage {}
```

## NetworkService Proto Method

Add a second `fetch` overload to the `NetworkService` protocol, alongside the existing `Decodable` one:

```swift
public protocol NetworkService: Sendable {
    // Existing JSON path
    func fetch<T: Decodable>(from endpoint: Endpoint, dateFormat: DateFormat?) async throws -> T

    // Proto path — for application/x-protobuf responses
    func fetch<T: WireMessage>(from endpoint: any Endpoint) async throws -> T
}
```

Call sites use type inference exactly as with the JSON path:

```swift
let response: Auth_AuthenticateResponse = try await networkService.fetch(from: AuthenticateEndpoint())
```

## NetworkServiceLive Implementation

`NetworkServiceLive` (in `NetworkingLive`) implements the proto fetch. It:

1. Calls `EndpointInterpreter.interpret(endpoint:)` to build the `URLRequest`
2. Injects `Accept: application/x-protobuf` into the request headers
3. Executes via `client.data(for:delegate:)` — the same `HTTPClient` retry/adapter loop
4. Decodes the response body with `T(serializedBytes:)` (the `WireMessage` initializer)

```swift
// NetworkingLive/Service/NetworkServiceLive.swift
public func fetch<T: WireMessage>(from endpoint: any Endpoint) async throws -> T {
    var request = EndpointInterpreter.interpret(endpoint: endpoint)
    request.setValue("application/x-protobuf", forHTTPHeaderField: "Accept")
    let (data, response) = try await client.data(for: request, delegate: nil)
    try response.validateSuccess()   // URLResponse+Success.swift
    return try T(serializedBytes: data)
}
```

The request **body stays JSON** (POST body encoding is unchanged); only the response decode path changes.

## Where Generated Code Lives

Generated Swift types are checked into the repo under a dedicated package:

```
ios/Packages/WireModels/
├── Package.swift                          ← depends on apple/swift-protobuf + Networking
└── Sources/WireModels/
    ├── Generated/
    │   └── jewdeal/auth/v1/
    │       └── auth.pb.swift              ← generated by buf.build/apple/swift
    └── WireMessage+Generated.swift        ← hand-written WireMessage conformances
```

`WireModels` is the **only** package that imports `SwiftProtobuf`. Feature packages import `WireModels` to access the concrete message types, and `Networking` for the `WireMessage` protocol.

## buf.gen.yaml Swift Plugin

The `buf.build/apple/swift` remote plugin is added alongside the existing TS plugin in `buf.gen.yaml`:

```yaml
plugins:
  - remote: buf.build/apple/swift
    opt: Visibility=Public
    out: ios/Packages/WireModels/Sources/WireModels/Generated
```

> **During development (before BSR publish):** run `buf generate proto` with a local-dir input to regenerate. The pinned-BSR-commit flow (CI `buf push` on merge → manual pin bump in `buf.gen.yaml`) is the steady state.

## Proto → Domain Mapping

Map generated wire messages to domain types at the **repository edge**, mirroring the existing DTO → domain mapper pattern:

```swift
// SessionLive/AuthenticateResponseMapper.swift
enum AuthenticateResponseMapper {
    static func map(_ response: Auth_AuthenticateResponse) -> AppSession {
        AppSession(
            token: response.token,
            user: .init(id: response.user.id, name: response.user.name),
            household: response.hasHousehold
                ? .init(id: response.household.id, members: response.household.members.map { ... })
                : nil
        )
    }
}
```

The repository calls `fetch<Auth_AuthenticateResponse>` and immediately maps — it never exposes the generated type to layers above it. This mirrors the DTO → domain pattern documented in the `ios-data-layer` skill.

## Endpoint Shape

Proto endpoints use the same `Endpoint` protocol as JSON endpoints — no special marker protocol is needed. The decode format is determined by the call site: calling `fetch<T: WireMessage>` routes through the proto path; `fetch<T: Decodable>` routes through JSON.

```swift
// A POST endpoint whose response is binary proto (request body stays JSON)
struct AuthenticateEndpoint: PostEndpoint {
    typealias Body = AuthenticateRequest

    var baseURL: BaseURL { .api }
    var path: String { "/authenticate" }
    var queryParameters: [String: String]? { nil }
    var headers: [String: String]? { nil }
    let requestBody: AuthenticateRequest?
}
```

## Testing the Proto Path

Test `NetworkServiceLive` proto behaviour by injecting a stub `NetworkClient` that returns hand-crafted binary data and verifying that the correct `Accept` header was set:

```swift
@Test func fetch_protoEndpoint_setsAcceptHeader() async throws {
    let expectedBytes = try Auth_AuthenticateResponse.with {
        $0.token = "tok"
        $0.user = .with { $0.id = "u1"; $0.name = "Alice" }
    }.serializedData()

    let stub = StubNetworkClient(response: (Data(expectedBytes), HTTPURLResponse.success))
    let service = NetworkServiceLive(client: stub, jsonDecoder: JSONDecoder())

    let result: Auth_AuthenticateResponse = try await service.fetch(from: AuthenticateEndpoint())

    #expect(stub.lastRequest?.value(forHTTPHeaderField: "Accept") == "application/x-protobuf")
    #expect(result.token == "tok")
}
```

For unit tests that mock `NetworkService` itself (e.g. repository tests), `@Mocked NetworkService` must support the generic `fetch<T: WireMessage>` overload — see the `swift-mocking` skill for `@Mocked` with multiple generic overloads.

## Rules

| Rule | Why |
|------|-----|
| `WireMessage` in `Networking` with no SwiftProtobuf import | Feature packages stay lightweight; only `WireModels` pulls the runtime |
| Generated code checked into repo | Mirrors the TS gen pattern; avoids build-time codegen on iOS |
| Map wire message → domain at repository edge | Keeps generated types out of domain/UI layers |
| Request body stays JSON | Only response decode changes; request encoding is unchanged |
| Same `Endpoint` protocol for proto and JSON | No per-endpoint format flag; call site chooses the decode path |
